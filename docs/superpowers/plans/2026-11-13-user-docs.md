# Player Docs and In-App Help Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three player docs in `docs/user/` (tutorial, beginner's guide, legal), shown on GitHub and inside the desktop and web apps from the same files, with entry points for new players.

**Architecture:** The Markdown and screenshots are embedded resources of Presentation. `HelpDocs` (Presentation) loads them and parses a small Markdown subset into blocks. The WPF `HelpWindow` and the Blazor `HelpViewer` draw those blocks.

**Tech Stack:** .NET 10, WPF, Blazor WebAssembly, xUnit. No new packages.

**Spec:** `docs/superpowers/specs/2026-11-13-user-docs-design.md`

## Global Constraints

- No new packages; the Markdown parser is hand-written.
- Presentation stays UI-neutral: parsing there, drawing in App and Web.
- Every new WPF input gets an `AutomationProperties.Name`; state is never shown by colour alone.
- Docs contain no rules text (see `NOTICE.md`); the beginner's guide explains the sheet in original wording.
- Supported Markdown: `#`/`##`/`###`, paragraphs, `-` bullets (one level), `**bold**`, `[text](url)`, `![alt](images/x.png)` alone on a line. Anything else renders as plain text.
- Wikidot URL: `https://dnd5e.wikidot.com`. Linked only, never embedded or scraped.
- Section anchors use GitHub slugs: lowercase, spaces become `-`, characters other than letters, digits, `-` and `_` are dropped.
- Only `http`/`https` links open in the browser; `*.md` links (optionally `#anchor`) navigate inside the viewer.
- Work on `feature/user-docs` from `origin/dev`, PR into `dev` (squash). No version bump.

## Review Focus

1. **Help opened from inside the modal New character dialog**: the help must appear on top and be usable, on desktop (a window shown after `ShowDialog` stays enabled) and on web (a second native `<dialog>` in the top layer, not queued behind the open one in `WebDialogs`). Checked manually in Tasks 3 and 4.
2. **Broken doc links or missing screenshots**: every link and image in the bundled docs must resolve. `HelpDocsTests.Bundled_docs_links_and_images_resolve` (Task 2).
3. **Markdown outside the subset** (`*` bullets, `1.` lists, `` `code` ``, tables, an unclosed `**`) renders as plain text, never throws. `Parse_unsupported_markdown_is_plain_text` (Task 1).
4. **An anchor that matches no heading** opens the doc at the top. `FindAnchor_missing_returns_minus_one` (Task 1).
5. **A non-http link target** (`file:`, `javascript:`) is never opened. `ResolveLink_rejects_other_schemes` (Task 1).

### Task 1: Markdown parser

**Files:**
- Create: `src/Hearthsheet.Presentation/HelpDocs.cs`
- Test: `tests/Hearthsheet.Tests/HelpDocsTests.cs`

**Interfaces:**
- Produces:
  ```csharp
  public enum HelpBlockKind { Heading, Paragraph, Bullet, Image }
  public sealed record HelpRun(string Text, bool Bold = false, string? Link = null);
  /// Level: 1-3 for headings. Anchor: slug, headings only. Image: path such as "images/x.png" and alt text in Runs[0].
  public sealed record HelpBlock(HelpBlockKind Kind, IReadOnlyList<HelpRun> Runs, int Level = 0, string? Anchor = null, string? Image = null);
  /// Exactly one of Url or Doc is set; Anchor may accompany Doc, or stand alone for a same-doc link (Doc null, Url null).
  public sealed record HelpLink(string? Url, string? Doc, string? Anchor);

  public static partial class HelpDocs
  {
      public const string WikidotUrl = "https://dnd5e.wikidot.com";
      public static IReadOnlyList<HelpBlock> Parse(string markdown);
      public static string Slug(string heading);
      public static int FindAnchor(IReadOnlyList<HelpBlock> blocks, string? anchor); // index, or -1
      public static HelpLink? ResolveLink(string target); // null = do nothing
  }
  ```

- [ ] **Step 1: Write the failing tests** in `HelpDocsTests`:
  - `Parse_headings_paragraphs_bullets`: `"# Title\n\nOne\ntwo\n\n- a\n- b"` gives Heading(Level 1, Runs "Title", Anchor "title"), Paragraph("One two"), Bullet("a"), Bullet("b").
  - `Parse_inline_bold_and_link`: `"Use **Play** and [the wikidot](https://dnd5e.wikidot.com)."` gives runs `("Use ")`, `("Play", Bold)`, `(" and ")`, `("the wikidot", Link "https://dnd5e.wikidot.com")`, `(".")`.
  - `Parse_image_line`: `"![The sheet](images/sheet.png)"` gives one Image block, `Image == "images/sheet.png"`, `Runs[0].Text == "The sheet"`.
  - `Parse_unsupported_markdown_is_plain_text`: `"* star\n1. one\n`code`\n| a | b |\n**open"` doesn't throw and every block is a Paragraph whose concatenated text contains `"* star"`, `"1. one"`, `"`code`"`, `"| a | b |"` and `"**open"`.
  - `Slug_matches_github`: `Slug("Creating a character") == "creating-a-character"`, `Slug("Saves & skills!") == "saves--skills"`, `Slug("Level 2: Spells") == "level-2-spells"`.
  - `FindAnchor_found_and_missing_returns_minus_one`: index of a heading with that slug; `-1` for `"nope"` and for `null`.
  - `ResolveLink_cases`: `"https://x.y"` → Url; `"beginners-guide.md"` → Doc; `"tutorial.md#creating-a-character"` → Doc + Anchor; `"#rests"` → Anchor only.
  - `ResolveLink_rejects_other_schemes`: `"file:///c:/x"`, `"javascript:alert(1)"` and `"mailto:a@b"` → null.
- [ ] **Step 2:** `dotnet test Hearthsheet.slnx --filter "FullyQualifiedName~HelpDocsTests"` → fails to compile.
- [ ] **Step 3: Implement** `HelpDocs.cs`. Line-based: blank lines end a paragraph; consecutive non-blank lines join with a space. Inline parsing scans for `**…**` and `[…](…)` pairs and leaves unmatched markers as literal text.
- [ ] **Step 4:** The same command → PASS.
- [ ] **Step 5:** Commit `feat: help markdown parser`.

### Task 3: Desktop help window and entry points

**Files:**
- Create: `src/Hearthsheet.App/Views/HelpWindow.xaml`, `HelpWindow.xaml.cs`
- Modify: `src/Hearthsheet.App/MainWindow.xaml` (Help menu at line 68; list empty state at line 155), `src/Hearthsheet.App/ViewModels/MainViewModel.cs`, `src/Hearthsheet.App/Views/NewCharacterDialog.xaml`, `NewCharacterDialog.xaml.cs`

**Interfaces:**
- Consumes: `HelpDocs.Load`, `LoadImage`, `FindAnchor`, `ResolveLink`, `Topics`, constants.
- Produces: `public static void HelpWindow.Open(string file, string? anchor = null)`. It reuses one instance (activates it and navigates), and is owned by `Application.Current.MainWindow`.

- [ ] **Step 1: `HelpWindow`.**
  - Layout: `AppWindow` style, about 640×720, resizable. A top bar with a **Back** button (`AutomationProperties.Name="Back"`, disabled when history is empty) and the doc title. Under it, a `ScrollViewer` holding a `StackPanel` built in code from blocks.
  - Blocks:
    - Heading: `TextBlock`, SemiBold, at sizes 22/17/14.
    - Paragraph: wrapping `TextBlock` with `Run`/`Bold`/`Hyperlink` inlines.
    - Bullet: the same, prefixed with "• ".
    - Image: `Image` with a `BitmapImage` from the `LoadImage` stream (`CacheOption=OnLoad`), `MaxWidth` 560, and `AutomationProperties.Name` set to the alt text.
  - Hyperlink click: `ResolveLink`. A Url goes to `Process.Start(new ProcessStartInfo(url) { UseShellExecute = true })`. A Doc or Anchor pushes the current doc onto history, then navigates.
  - Navigation scrolls the target heading into view (`BringIntoView` after layout), or goes to the top when `FindAnchor` is -1.
- [ ] **Step 2: Menu.** Above the existing Help items, insert **_Tutorial**, **_Beginner's guide to 5e**, **Look up rules (D&D 5e _wikidot)**, a separator, **_Legal and credits**, and another separator. They're bound to `MainViewModel.ShowHelp` (a `RelayCommand<string>` opening `HelpWindow.Open(param)`) and `OpenWikidot` (Process.Start `HelpDocs.WikidotUrl`).
- [ ] **Step 3: Empty character list.** Under the "No characters yet…" `TextBlock`, add a `TextBlock` with a `Hyperlink` reading "New to Hearthsheet? Read the tutorial". It gets the same visibility binding, and its command is `ShowHelp` with `tutorial.md`.
- [ ] **Step 4: New character dialog.** Next to the hint, add a `Hyperlink` "Need help?" whose click calls `HelpWindow.Open(HelpDocs.Tutorial, HelpDocs.CreatingACharacter)`.
- [ ] **Step 5: Verify.**
  - `dotnet build Hearthsheet.slnx` succeeds.
  - Run the app on a scratch data folder (see Task 5, Step 1), then:
    - Open each Help item.
    - Follow the wikidot link and an in-doc link, then Back.
    - Open File → New character…, click **Need help?**: the help window appears on top, is scrollable, and lands on "Creating a character". Close it, and the dialog still works.

- [ ] **Step 2: `HelpViewer.razor`.**
