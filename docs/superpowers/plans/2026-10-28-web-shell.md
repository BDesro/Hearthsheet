# Web shell (Phase 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A signed-in, offline-capable Blazor WebAssembly app that lists, creates, imports, exports, deletes and syncs
characters with the desktop, deployed by the release workflow behind a preview banner. The server also gets migration
`0002` (caps, grants, sign-up allowlist).

**Architecture:**
- Shared, testable logic goes into the existing `net10.0` projects:
  - Presentation: async `IDialogs`, a `ShellViewModel` extracted from the desktop's `MainViewModel`, and the shared
    sync status texts.
  - Core: `MemoryCharacterStore`, an in-memory `ICharacterRepository` + `ISyncLocalStore` that writes every change as a
    batch to an `IStoreJournal`.
  - Cloud: an optional session-only secret store in `SupabaseAuth`, plus `SecretRedactor` (moved from Infrastructure).
- New `src/Hearthsheet.Web` (Blazor WebAssembly PWA):
  - It is thin: Razor components, one JS module (IndexedDB, Web Locks, BroadcastChannel, browser events, downloads),
    the service worker and `_headers`.
  - It composes the same `CloudSync`, `SupabaseAuth` and `ShellViewModel` the desktop uses.
- The Play, Details and Sheet views are Phases 3–5. Phase 2 shows the open character's name (editable) as a
  placeholder, enough to exercise autosave and sync.

**Tech Stack:** .NET 10, Blazor WebAssembly (PWA), xUnit, Supabase (Postgres, Auth hook), Cloudflare Pages with
`wrangler` via `npx`, Playwright or the built-in browser for browser checks.

**Spec:** `docs/superpowers/specs/2026-10-28-web-version-design.md`. This plan implements Phase 2: decisions 3 (web
handler), 5, 6, 7, 7a, 8, 9 (Export all), 10, 11, 12, 13, 14, 15, 15a, 16, 17, 18, 19, 20 and the Phase 2 rows of 22
(Download diagnostics).

## Global Constraints

- Dependencies point inward:
  - `Web` → `Presentation`, `Cloud` → `Core`
  - `Presentation` → `Core`
  - `Web` never references `Infrastructure` or `App`.
- No new NuGet packages except Microsoft's Blazor WebAssembly packages (`Microsoft.AspNetCore.Components.WebAssembly`,
  `…WebAssembly.DevServer`) in `Hearthsheet.Web`. No npm toolchain. `wrangler` runs only through `npx` at a pinned exact
  version, and only in the release job (plus optionally locally in Task 14).
- **Core stays the single home of the game rules.** The web calls Core; it never reimplements a rule or a summary
  text.
- Hand-written JS: only `wwwroot/js/hearthsheet.js` and the service worker files.
- No inline scripts or styles in `index.html` or components. `MarkupString` is banned in `Hearthsheet.Web`.
- No third-party scripts, fonts, analytics or CDNs at runtime.
- CSP (verbatim, decision 16):
  - `default-src 'self'`
  - `script-src 'self' 'wasm-unsafe-eval'`
  - `connect-src 'self'` plus the one Supabase project URL
  - `style-src 'self'`
  - `img-src 'self' data: blob:`
  - `object-src 'none'`
  - `base-uri 'self'`
  - `form-action 'none'`
  - `frame-ancestors 'none'`
- Other headers:
  - `Strict-Transport-Security`
  - `X-Content-Type-Options: nosniff`
  - `Referrer-Policy: no-referrer`
  - a restrictive `Permissions-Policy`
  - `Cross-Origin-Opener-Policy: same-origin`
- The web build points at **Hearthsheet-Test** until the launch gate. It shows a "preview" banner. Tests never hold
  production credentials.
- Exact user-facing texts (from the spec and the desktop; en dashes as written):
  - "Not saved on this device"
  - "Hearthsheet is open in another tab"
  - "A new version is ready – reload"
  - "{N} changes not yet synced" (singular "1 change not yet synced")
  - "Signed out – sign in to resume sync"
  - "Sign-ups are closed. Ask Beau to add your email."
  - Sync statuses: whatever the desktop's `SyncViewModel` shows today, shared, not copied (Task 3).
- `Relink` is never called on the web (spec decision 4). No `.Wait()`, `.Result` or `GetAwaiter().GetResult()` on the
  web's code path.
- Every input has an accessible name (`<label for>` or `aria-label`). State is never shown by colour alone.
- Parameterized SQL only. Never log secrets or tokens.
- The desktop keeps working. All existing tests pass after every task, and Task 14 repeats the desktop smoke check.
- Branch `web-shell` from `dev`; one PR into `dev`. Never push to `dev` or `main`.
- Commit messages end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **The tab is closed or reloaded while IndexedDB writes are still queued.** Expected: nothing saved in memory is lost.
   - `visibilitychange` → hidden saves the open character and flushes the journal.
   - The update reload does the same before reloading.
   - Browser check in Task 11, step "close mid-edit".
2. **The session expired or was revoked, and the app starts offline.** Expected: the last account's characters open
   for editing with "Signed out – sign in to resume sync". Nobody is locked out at the table.
   - Test `WebStartupTests.OpensLastAccount_WhenSessionCannotBeRestored` (Task 10).
   - Browser check in Task 14.
3. **Person B signs in on a browser that holds person A's unsynced changes.** Expected: B sees only B's characters,
   nothing of A's is uploaded to B, and A's store is untouched for when A signs in again.
   - Test `CloudSyncTests.WebStoresArePerAccount` (Task 4).
   - Browser check in Task 14.
4. **Two tabs open at once, including both starting in the same instant.** Expected: exactly one holds the lock. The
   other shows "Hearthsheet is open in another tab". Take over saves and releases the first before the second loads.
   - Browser check in Task 9.
5. **IndexedDB is unavailable or a write fails** (private window, quota, storage cleared mid-session). Expected: a
   visible "Not saved on this device", never a blank page or a silent loss. A later successful write clears it.
   - Browser check in Task 8 with the `failNextWrites` hook.

Blazor can't block for a modal, so every dialog the shared view models ask becomes awaitable. WPF returns completed
tasks, so desktop behaviour and ordering don't change.

**Files:**

- Modify: `src/Hearthsheet.App/Dialogs.cs`

**Interfaces:**
- Produces:

```csharp
public interface IDialogs
{
    Task<bool> ConfirmAsync(string message, string title = "Confirm");
    Task InfoAsync(string message);
    Task ErrorAsync(string message);
    Task<NewCharacterOptions?> NewCharacterAsync();
    Task<(string ClassName, LevelUpOptions Options)?> LevelUpAsync(Character c, string? className = null);
    Task<QuickAddResult?> QuickAddAsync(string title, IReadOnlyList<object>? kinds, object? defaultKind, bool withDescription);
    Task<bool> ShortRestAsync(PlayViewModel play, Character character);
```

**Files:**

**Interfaces:**
- Produces:

```csharp
namespace Hearthsheet.Core.Storage;

/// <summary>One persisted record: Json null removes the key.</summary>
public sealed record StoreRecord(string Key, string? Json);

/// <summary>Receives each store change as one batch, in order. Must not block.</summary>
public interface IStoreJournal { void Write(IReadOnlyList<StoreRecord> batch); }

public sealed class MemoryCharacterStore : ICharacterRepository, ISyncLocalStore
{
    public MemoryCharacterStore(IEnumerable<StoreRecord> saved, IStoreJournal journal, ILogger<MemoryCharacterStore> logger, TimeProvider? time = null);
    public int UnsyncedCount { get; }   // dirty rows + pending deletes
}
```

- Keys:
  - `c:{id}`: a character row with `Id`, `Name`, `Description`, `SchemaVersion`, `Data`, `CreatedUtc`, `UpdatedUtc`,
    `CloudRevision`, `Dirty`, `LocalRevision`, as JSON. The type is internal and serialized with a source-generated
    `JsonSerializerContext`, so trimming can't break it.
  - `d:{id}`: a pending delete's cloud revision.
  - `m:sync_account`, `m:sync_last_pull`.
- Every public method mirrors `SqliteCharacterRepository`'s SQL statement for statement:
  - Same dirty, revision and pending-delete rules.
  - `List` is ordered by name, case-insensitive.
  - `Load` deserializes with `CharacterJson.Deserialize(data, schemaVersion)`.
  - Each method changes memory, then calls `journal.Write` once with every record it changed. `ResetSyncState` and
    `ReassignAllIds` are one batch each.
  - No method awaits (spec decision 10).
- An unreadable record at construction is skipped, logged as a warning and left in storage (never removed).

### Task 6: Migration `0002`: grants, caps and the sign-up allowlist

Independent of every other task.

**Files:**

**Contents of `0002_guardrails.sql`:**
- `revoke all on public.characters from anon, authenticated;` then grant exactly what `0001` grants:
  - `select, insert, update` to `authenticated`
  - `select` to `anon`
- `alter table public.characters add constraint characters_data_size check (data is null or octet_length(data::text) <= 1048576);`
  (1 MB; about 60× a real 17 KB character).
- A per-user cap of **100** rows (live plus tombstones):
  - a `before insert` trigger function `public.characters_cap()` with `set search_path = ''`
  - it takes `pg_advisory_xact_lock(hashtextextended(new.user_id::text, 0))` and counts
    `public.characters where user_id = new.user_id`
  - at 100 or more, it raises `'Character limit reached (100). Delete some characters or ask Beau.'` with
    `errcode = 'P0001'`
- Allowlist:
  - `create schema if not exists private;` and
    `create table private.signup_allowlist (email text primary key, added_at timestamptz not null default now(), source text not null);`
  - Seed it with `select lower(trim(email)), 'existing' from auth.users where email is not null on conflict do nothing`.
- Hook function `public.hook_before_user_created(event jsonb) returns jsonb`, `security definer`, `set search_path = ''`:
  1. Normalize `event->'user'->>'email'` with `lower(trim(...))`.
  2. Take `pg_advisory_xact_lock(hashtextextended('signup_allowlist', 0))`.
  3. If the email is listed, return `'{}'::jsonb`.
  4. Else, if the list has fewer than **10** rows, insert it with `source = 'auto'` and return `'{}'`.
  5. Else return `jsonb_build_object('error', jsonb_build_object('http_code', 403, 'message', 'Sign-ups are closed. Ask Beau to add your email.'))`.

  The limit 10 is a constant in the function.
- Grants for the hook:
  - `grant usage on schema private to supabase_auth_admin`
  - `grant select, insert on private.signup_allowlist to supabase_auth_admin`
  - `grant execute on function public.hook_before_user_created to supabase_auth_admin`
  - `revoke execute on function public.hook_before_user_created from public, anon, authenticated`
  - `revoke all on schema private from anon, authenticated`

### Task 8: Browser storage

**Files:**
- Modify: `src/Hearthsheet.Web/wwwroot/js/hearthsheet.js`
- Create: `src/Hearthsheet.Web/Storage/IndexedDbJournal.cs`, `Storage/BrowserSecretStore.cs`, `Storage/BrowserStorage.cs`

**Interfaces:**
- JS exports (IndexedDB database per name, one object store `records`, key = `StoreRecord.Key`, value = JSON string):
  - `idbLoad(dbName)` → `[{key, json}]`
  - `idbWrite(dbName, batch)`: one readwrite transaction; resolves on `complete`, rejects on `error`/`abort`
  - `idbDelete(dbName)`
  - `persist()`
  - `local(key)` / `setLocal(key, value|null)`
  - `session(key)` / `setSession(key, value|null)`
  - A test-only hook `failNextWrites(n)` (exported, never called by app code)
- `IndexedDbJournal : IStoreJournal`:
  - `Write` enqueues the batch and starts a pump if idle. The pump awaits `idbWrite` one batch at a time, in order.
  - On failure it keeps the batch at the head, sets `Failed = true` and raises `StateChanged`, then retries on the next
    `Write` or on `RetryAsync()`. On a later success it clears `Failed`.
  - `Task FlushAsync()` completes when the queue is empty or a write has failed.
- Database names: app data `hearthsheet-app`; per account `hearthsheet-u-{userId}`.
- `BrowserSecretStore : ISecretStore`: an in-memory dictionary loaded from `hearthsheet-app` at startup. Writes go
  through its own `IndexedDbJournal`. Used as `secrets` for "Stay signed in".
- `SessionSecretStore : ISecretStore` over `sessionStorage` through `IJSInProcessRuntime` (synchronous). Used as
  `sessionSecrets`.
- The last account in `localStorage` under `hearthsheet.lastAccount` as JSON `{userId, email}` (not a secret). Task 10
  defines the `LastAccount` record in Presentation; until then read and write it as two strings.
- `BrowserStorage.OpenAccountAsync(string userId)` → `MemoryCharacterStore` (loads all records first, spec decision 6),
  and `ForgetAccountAsync(userId)`.
